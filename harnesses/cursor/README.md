# Cursor Agent CLI adapter

**Design documented; custom-provider support is blocked by the current public CLI contract.**

This research-only design is outside the currently approved eight-adapter v1 implementation set and is not an implementation candidate while the blocker remains.

Read the [adapter specification](SPEC.md) and [overall specification](../../SPEC.md).

| Item | Planned behavior |
| --- | --- |
| Proposed adapter ID | `cursor` |
| Native executable | `agent` (current primary command); `cursor-agent` is a compatibility alias |
| Provider command | Undecided until a routable provider interface exists |
| Role selection | Native `--model` exists, but does not configure a canonical provider endpoint/key |
| Native configuration | `~/.cursor/cli-config.json` or `CURSOR_CONFIG_DIR` |
| Default files | No writes proposed |
| Verified releases | None; no installed release or documented CLI BYOK interface is available |

## Current compatibility conclusion

Cursor Agent CLI documents model selection through `--model` and `/model`, and Cursor-account authentication through browser login or `CURSOR_API_KEY`. That key is generated by Cursor and authenticates the Cursor service; it is not a third-party LLM provider key. The public CLI configuration schema contains a model selection but no documented arbitrary provider base URL, provider type or provider credential fields.

Cursor's desktop editor separately documents BYOK setup in its Models settings UI. It does not publish a supported file schema that this tool can safely render, and editor credential storage is outside the CLI adapter boundary. Consequently, an adapter cannot currently consume this project's canonical endpoint, protocol, API key and exact model tuple without ignoring or misusing fields. This directory records the design and blocker rather than claiming false support.

## Implementation boundary

This directory is documentation-only. No adapter manifest, `adapter.py`, registry entry, wrapper installation or Cursor configuration change has been added. Do not implement the adapter until Cursor publishes a stable noninteractive custom-provider interface, or the overall schema is separately expanded and approved to model Cursor-hosted service accounts. Re-check the linked official documentation before implementation because the CLI is actively evolving.
